Privacy policy

Keywarden collects nothing. There are no accounts, no servers of ours, no analytics and no crash reports. Your passwords stay in a .kdbx file on your computer.

Last updated: 11 November 2026. Applies to the Keywarden app (keywardend, keywarden-ui, kw, keywarden-host) and the Keywarden browser extension for Firefox, Chrome and Edge.

What is stored and where

  • Your vault. A KeePass .kdbx file in a folder you choose, encrypted with your master password (and key file or YubiKey, if you use them). If you put it in Syncthing, Dropbox or another sync folder, that service handles the file under its own terms; Keywarden only reads and writes the file.
  • Settings. A config file in your user's config folder (for example ~/.config/keywarden). It holds preferences, never passwords.
  • Browser extension. In the browser's local extension storage: its preferences, password generator options, the keys that pair it with the app, and for each site where you filled a login, which entry you picked last (the site's host name and the entry id, so it is offered first next time). It does not store passwords, page contents, form contents or browsing history. Removing the extension deletes all of it.

The browser extension

The extension talks only to the Keywarden app on the same computer, through the browser's native messaging channel. Messages are encrypted end to end between the extension and the app. It sends nothing to the internet and has no remote code.

To fill a login it reads the address of the current tab and finds the login form on the page. The address is used to pick matching entries in your vault; only the host name of a site where you actually filled a login is remembered, as described above. Permissions and why they are needed:

  • nativeMessaging: connect to the Keywarden app on your computer.
  • activeTab, tabs, scripting: see the current tab's address and fill the login form on it.
  • storage: keep the extension's own preferences.
  • favicon (Chrome and Edge): show site icons from the browser's own cache in the popup.

Network requests

The app works fully offline. It goes online only in the cases below, and each one starts from your action or a setting you turned on. Requests go straight from your computer to the named service; we never see them.

  • Update check, off by default. When on, it asks GitHub (api.github.com) for the latest release number.
  • Leaked password check, when you run it in Vault health or turn on scheduled checks (off by default). Uses the Have I Been Pwned range API (api.pwnedpasswords.com): only the first 5 characters of each password's SHA-1 hash are sent, never the password or the full hash.
  • 2FA and passkey hints, when you press the button in Vault health. Downloads public lists from 2fa.directory. Nothing about your vault is sent.
  • Site icon, when you ask for an entry's icon. Loads the icon from that entry's website, like opening the site would.
  • Block explorer links for crypto wallet entries open in your browser only when you click them.

Third parties

We do not sell, share or transfer any data, because we do not have any. This website is static, hosted on GitHub Pages, and loads nothing from third parties (fonts are self-hosted). GitHub may keep standard server logs for it under the GitHub Privacy Statement.

Changes and contact

Changes to this policy are made in the open in the repository, with the date above updated. Questions: open an issue, or for a security problem use private vulnerability reporting.
