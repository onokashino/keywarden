Политика приватности

Keywarden ничего не собирает. Нет аккаунтов, нет наших серверов, нет аналитики и отчётов о сбоях. Пароли лежат в файле .kdbx на вашем компьютере.

Обновлено 11 ноября 2026. Относится к приложению Keywarden (keywardend, keywarden-ui, kw, keywarden-host) и расширению Keywarden для Firefox, Chrome и Edge.

Что хранится и где

  • База. Файл KeePass .kdbx в папке, которую вы выбрали, зашифрованный мастер-паролем (и ключевым файлом или YubiKey, если они есть). Если база лежит в папке Syncthing, Dropbox или другой синхронизации, файлом распоряжается этот сервис по своим правилам; Keywarden только читает и пишет файл.
  • Настройки. Файл в папке настроек пользователя (например ~/.config/keywarden). В нём предпочтения, паролей там нет.
  • Расширение браузера. В локальном хранилище расширения: свои настройки, параметры генератора паролей, ключи сопряжения с приложением и для каждого сайта, где вы заполняли вход, какую запись выбрали последней (имя сайта и id записи, чтобы в следующий раз предложить её первой). Пароли, содержимое страниц и форм и историю посещений оно не хранит. При удалении расширения всё это удаляется.

Расширение браузера

Расширение общается только с приложением Keywarden на этом же компьютере через канал native messaging браузера. Сообщения между расширением и приложением зашифрованы. В интернет оно ничего не отправляет и не загружает код со стороны.

Чтобы заполнить вход, оно читает адрес текущей вкладки и находит форму входа на странице. Адрес нужен, чтобы подобрать записи из базы; запоминается только имя сайта, где вы действительно заполнили вход, как описано выше. Разрешения и зачем они нужны:

  • nativeMessaging: связь с приложением Keywarden на компьютере.
  • activeTab, tabs, scripting: узнать адрес текущей вкладки и заполнить на ней форму входа.
  • storage: хранить настройки самого расширения.
  • favicon (Chrome и Edge): показывать значки сайтов из кэша самого браузера.

Запросы в сеть

Приложение полностью работает без сети. В интернет оно ходит только в случаях ниже, и каждый начинается с вашего действия или включённой вами настройки. Запросы идут с вашего компьютера прямо в указанный сервис, мы их не видим.

  • Проверка обновлений, по умолчанию выключена. Если включить, спрашивает у GitHub (api.github.com) номер последней версии.
  • Проверка утёкших паролей, когда вы запускаете её в «Здоровье базы» или включаете проверку по расписанию (по умолчанию выключена). Использует range API Have I Been Pwned (api.pwnedpasswords.com): уходят только первые 5 символов SHA-1 хеша каждого пароля, но не пароль и не хеш целиком.
  • Подсказки про 2FA и ключи доступа, по кнопке в «Здоровье базы». Скачивает открытые списки с 2fa.directory. Ничего о вашей базе не отправляется.
  • Значок сайта, когда вы просите значок для записи. Загружает его с сайта этой записи, как при обычном открытии сайта.
  • Ссылки на обозреватели блоков у криптокошельков открываются в браузере, только когда вы по ним нажимаете.

Третьи лица

Мы не продаём, не передаём и не пересылаем данные: у нас их просто нет. Этот сайт статический, размещён на GitHub Pages и ничего не грузит со сторонних серверов (шрифты лежат здесь же). GitHub может вести обычные журналы сервера по своему заявлению о конфиденциальности.

Изменения и связь

Политика меняется открыто в репозитории, дата выше обновляется. Вопросы: создайте issue, а о проблеме безопасности сообщите через закрытый отчёт об уязвимости.
